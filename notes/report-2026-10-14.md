# CoT-Control × SWITCH: overnight report (2026-10-14)

Snapshot of `/workspace/results/cot-control-switch/full1`, taken 14:03 UTC.

Every number below was recomputed from the raw rows with fresh code (`verify/recompute.py` and `tables.py` copied to `notes/verify/`), not taken from `analyze.py`. Where `analyze.py` also reported a figure, the two agree.

## Bottom line

- **The run is incomplete, and the key control is missing.**
  - **switch-nolatent never ran at full scale.** It was queued behind qwen3-8b on vLLM.
  - **qwen3-8b reached only half of the default protocol** (6,091 of 12,050 rows).
  - So nothing here separates the effect of **latent mode** from the effect of **SWITCH's fine-tuning**. That needs switch-nolatent.
- **SWITCH-latent complies more than its base model, but mostly through format.**
  - Default protocol, same items: **9.8% vs 1.8%**, a difference of +8.0 pp (95% bootstrap CI 5.8 to 10.1), n = 891 pairs over 6 constraints.
  - Part of the gap is SWITCH reasoning in the visible response after an empty `<think>`. Counting only the think span: 7.1% vs 1.8%.
  - Part is degenerate loops ("meow meow …") that the reference grader scores as compliant.
- **Argon (SWITCH-latent only):** pooled strict **7.7%** (285 / 3,690; Wilson 6.9 to 8.6), continuous 48.1%.
  - Counting only the think span, strict drops to **1.8%**.
  - Most Argon passes come from SWITCH leaving `<think>` empty and writing short compliant reasoning in the response (e.g. start_ok: 16.1% as graded, 0.0% think-only).
- **SWITCH stops at about 2k total tokens.**
  - In 23.5% of default rows and 8.2% of Argon rows, SWITCH emits EOS mid-reasoning, with no answer, at a total length (prompt plus output) of about 2,048 tokens. That is often right after a latent block (`…is a<swi></swi><|im_end|>`).
  - Base Qwen3-8B never does this (0 / 6,091).
  - It happens under both the vLLM and HF engines, so it is a property of the model (consistent with a ~2k RL budget), not of our loop. It makes SWITCH's accuracy and some compliance numbers hard to interpret.
- **Latent use does not buy compliance in these data.** Rows with at least one latent block comply *less* than rows without, within every output-length quartile (Argon: 12.5 vs 19.4%, 6.0 vs 10.2%, 2.3 vs 4.7%, 0.5 vs 7.2%). This is correlational only.

## Engineering

- **Batched SWITCH loop:** rewritten as a paged-KV engine with the state machine on the GPU, CUDA graphs and lossless swap preemption.
  - About 13× faster than the first version: 840 vs 65 tokens/s, measured while sharing the GPU with vLLM.
  - Latent blocks are identical to the reference loop before the first token difference in 68 of 68 prompts.
- **Robustness:** every row is fsynced as it finishes and graded inline; runs resume by key.
- **Pod time:** mats3-migration (1×H200, $5.29/hr) ran about 11 h this session, about $58. It was already running when the session began.
