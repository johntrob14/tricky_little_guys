# gpt-oss-120b-generated trace cleanup

## Scope and volume

Ethan requested cleanup of traces generated by gpt-oss-120b, with the same procedure as the DeepSeek workflow, and a data-volume estimate before the gpt-oss stage starts. The editor remains DeepSeek; gpt-oss-120b is the source model.

The 2026-10-24 inventory covers 1,016/1,016 local `.eval` paths under `arena/`, excluding virtual environments and vendored environment code. It identifies 1,970/1,970 completed gpt-oss-120b episode records, representing 1,892/1,970 distinct message contents after normalizing IDs and serving metadata. Header/schema reads fail for 68/1,016 paths across all models; these are excluded from the inventory.

The same cleanup rules yield 5/48 post-fix standard attack transcripts, containing nonempty reasoning in 32/111 assistant turns and 11,756 reasoning characters before editing. All 5/5 are already included in the 117/117-source `deepseek_cleaned_v2` dataset and its queued follow-on. Additional eligible sources beyond that existing run are 0/5. `inventory.json` records the source identities and content hashes.

Other available source groups remain outside the selection:

| Source group | Pass the other quality filters | Turns with reasoning / assistant turns |
|---|---:|---:|
| Standard attacks before the scorer-oracle fix | 86/816 | 1,292/1,331 |
| Post-fix controls, without the attack-prompt context | 8/298 | 181/181 |

The standard quality filters require both scorer passes, a submit call, no sample/tool-parse error, and nonempty reasoning; recovered tool-result errors are allowed. Post-fix provenance requires a recorded revision descended from `f8274d7`. Older and control-condition traces are not added to this batch. The older attack candidates include multiple reasoning blocks in an assistant turn in 30/86 transcripts; the current editor accepts one reasoning block per turn, so those candidates also require an input-format adaptation.
